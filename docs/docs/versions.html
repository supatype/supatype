Versions

What each part of a Supatype release is at, so you can tell which versions go together.

Pre-1.0: APIs and config may change between releases.

What a release is made of

A release is one number for the CLI and every @supatype/* package. The engine, server and Postgres images it runs, and the Deno that functions run on, are pinned by that release and move with it, not with the newest image on Docker Hub.

ComponentVersionWhat it is
CLI and npm packages0.9.2The latest release, 2026-11-12. The published @supatype/* packages, such as @supatype/client and @supatype/react, carry the same number
Schema enginev0.11.2Parses the schema, plans and applies a push (supatype/schema-engine)
Serverv2.6.1The Supatype server: the API, auth and the services behind it (supatype/server)
Postgres17.2.16The database image, with its extensions (supatype/postgres)
Deno2.9.8The runtime for functions and hooks

The pins come from release/images.json in the repository, and the page is generated from it, so it is out of date only between a pin changing and the next site sync.

There is no 0.4, 0.5 or 0.6

The CLI went from 0.3.6 straight to 0.7.0, on npm and as git tags. Nothing is missing from the changelog: those versions were never released.

Check what you run

supatype --version prints the CLI version. A self-hosted stack pins the images in its rendered compose file; supatype self-host compose up -d renders it again after an upgrade.
