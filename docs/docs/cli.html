CLI

Every supatype command, grouped by what it is for. Descriptions are the ones supatype --help prints.

Pre-1.0: APIs and config may change between releases.

Install and help

terminal
$ npm install -g @supatype/cli
$ supatype --help
$ supatype push --help

Run commands from the project directory, where supatype.config.ts is. Every command also takes --project-name <name>, which names the project for this run over supatype.config.ts. supatype --version prints the CLI version.

Many commands that reach a database take --connection <url> to override the config, and --env <name> to pick an environment when the project is linked.

CLOUD

Commands marked Cloud need Supatype Cloud, which is coming soon. Everything else works locally and on a self-hosted stack.

Schema and database

CommandDescriptionUseful flags
pushPush schema to the database: diff, prompt for destructive changes, apply migration, generate types--yes, --connection <url>, --env <name>, --overwrite-drift
diffShow planned schema changes without applying them (dry run)--connection <url>, --env <name>
generateRegenerate TypeScript types without running a migration--connection <url>
migrateWrite the SQL a push would apply, without applying it. Plain, it takes no lock your application waits on and the file records nothing: applied by hand, the next push finds the tables unmanaged. With --record the file also records the migration as a push does-o, --output <file>, --record, --force
migrations listList applied migrations with schema snapshot metadata--connection <url>, --env <name>
rollbackRoll back the last applied migration--sync-schema, --no-sync-schema
resetDrop all managed tables and re-apply the schema from scratch (destructive)--yes, --connection <url>
rename [from] [to]Record a rename in supatype/renames.json, so every push applies it as a rename and keeps the data: supatype rename member.name member.title, or supatype rename member members for a table--prune
doctorReport schema drift between schema/index.ts and the live database--strict, --rebaseline, --accept-access-drift, --yes
adoptHand Supatype the objects a push refuses because their names are taken; take objects back with --release, and hand them back with --reclaim--release <object...>, --reclaim <object...>, --key <object...>, --adopt-none, --yes
pullScaffold schema/index.ts from live database introspection (draft, review before push)--connection <url>, --out <path>, --dry-run
introspectIntrospect the live Postgres database (JSON or summary)--json, --out <path>
db checkCheck whether a database meets Supatype's requirements (for external Postgres)--connection <url>, --schema <name>, --emit, --fix, --authenticator-password <password>
types checkValidate generated client augmentation wiring

An object passed to adopt is named as doctor names it: kind:table.name, or kind:name for a table. Studio shows the result under Schema objects.

PULL

pull writes a draft. Review it before you push: it types every uuid id column as SupatypeAuthUserId and does not write tableName, so fix those by hand.
