Deploy to a VM with GitHub Actions

Create a project on your laptop, push it to GitHub, run the stack on a VM with Docker Compose, and ship schema and frontend changes on every push to main.

Pre-1.0: APIs and config may change between releases.

What you will have

  • One repository with supatype.config.ts, shared by local development and the VM.
  • A VM running supatype self-host compose, with the gateway on port 18473.
  • A GitHub Action that connects over SSH, pulls, migrates, rebuilds static files and restarts Compose.
SCOPE

This guide covers self-hosting only. Supatype Cloud is a separate product.

Create the project locally

On your machine, with Node.js 22 or later.

1

Scaffold

terminal
$ npm install -g @supatype/cli
$ mkdir my-blog && cd my-blog
$ supatype init
$ npm install
$ supatype keys

Copy the printed ANON_KEY and SERVICE_ROLE_KEY into .env for local development.

2

Add a static frontend

terminal
$ supatype app add --static ./public
$ npm install -D vite
# in package.json: "build": "vite build", with output in public/

Commit supatype.config.ts. You do not run app add again on the server.

3

Develop, then push to GitHub

terminal
$ supatype dev
$ supatype push

Optionally proxy to Vite from a gitignored supatype.local.config.ts while production stays static. See Deploy changes.

terminal
$ git init
$ git add .
$ git commit -m "Initial Supatype project"
$ git branch -M main
$ git remote add origin git@github.com:YOUR_USER/my-blog.git
$ git push -u origin main

Prepare the VM

A one-time setup on Ubuntu 22.04 or similar, with SSH access.

4

Install the tools and clone

vm
# Docker: https://docs.docker.com/engine/install/ubuntu/
$ sudo apt update && sudo apt install -y git nodejs npm
$ sudo npm install -g @supatype/cli

$ sudo mkdir -p /opt/my-blog
$ sudo chown "$USER":"$USER" /opt/my-blog
$ cd /opt/my-blog
$ git clone git@github.com:YOUR_USER/my-blog.git .
5

Write the production secrets

Create /opt/my-blog/.env on the server and never commit it. Use strong values and your public URLs:

/opt/my-blog/.env
DATABASE_URL=postgresql://supatype_admin:CHANGE_ME@localhost:5432/my-blog
POSTGRES_USER=supatype_admin
POSTGRES_PASSWORD=CHANGE_ME
POSTGRES_DB=my-blog
JWT_SECRET=CHANGE_ME          # at least 32 characters: openssl rand -base64 48
ANON_KEY=eyJ...            # from supatype keys on first setup
SERVICE_ROLE_KEY=eyJ...
API_EXTERNAL_URL=https://api.example.com
SITE_URL=https://example.com
6

First boot

vm
$ cd /opt/my-blog
$ npm install
$ supatype self-host compose render
$ supatype self-host compose up -d
$ supatype push
$ npm run build
$ supatype self-host compose render
$ supatype self-host compose up -d

Open http://YOUR_VM_IP:18473, with Studio at /studio/. Put Nginx or Caddy in front for HTTPS.

Repository secrets

In your repository, open Settings → Secrets and variables → Actions and add:

SecretValue
VM_HOSTPublic IP or hostname of the VM
VM_USERSSH user, for example ubuntu
VM_SSH_KEYPrivate key (PEM) that can log in as VM_USER
DEPLOY_PATHProject directory on the VM, for example /opt/my-blog
NOTE

The workflow never uploads .env. Production secrets stay on the VM.

The workflow

Add .github/workflows/deploy-self-host.yml to your repository:

.github/workflows/deploy-self-host.yml
name: Deploy self-host

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy over SSH
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.VM_HOST }}
          username: ${{ secrets.VM_USER }}
          key: ${{ secrets.VM_SSH_KEY }}
          script_stop: true
          script: |
            set -euo pipefail
            cd "${{ secrets.DEPLOY_PATH }}"
            git fetch origin main
            git reset --hard origin/main
            npm ci
            supatype push
            npm run build
            supatype self-host compose render
            supatype self-host compose up -d

On every push to main the VM pulls the latest code, applies schema migrations, rebuilds public/ and refreshes Compose.

NOTE

supatype push reads DATABASE_URL from the VM's .env, which points at the Compose Postgres on localhost:5432. If you would rather not install the CLI globally on the VM, use npx @supatype/cli in the script.

Verify the pipeline

7

Push a change

terminal
$ git add .
$ git commit -m "Add posts and update the landing page"
$ git push origin main

Watch the run under Actions on GitHub. When it succeeds, load your gateway URL and check that the schema and static files changed.

If something fails

SymptomCheck
SSH failsThe firewall allows port 22, and VM_SSH_KEY matches the VM's authorized_keys.
supatype push failsCompose is up, and DATABASE_URL points at localhost:5432.
Site unchangednpm run build writes to the directory in app.static_dir, then re-run compose render and up -d.
