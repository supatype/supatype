# Changelog

## Unreleased

### Features

* **schema:** `Geo` takes its shape: `Geo<"polygon">` and `Geo<"linestring">` declare those
  geography columns, and a bare `Geo` is `Geo<"point">`. It claimed point, polygon or linestring
  while every `Geo` field compiled to a point. `GeoShape` names the three.

### Documentation

* **hooks:** `ModelMeta.hooks` and `ModelHookOptions.function` name a directory under `hooks/`,
  where the CLI and the functions worker look, not `functions/`. The hook docs no longer say the
  `service_role` key bypasses a hook: the server runs hooks for every write through the API, that
  key included.

## 0.7.0

Highlights: identity and generated columns; `AutoIncrement` as an identity by default and a
`Block`'s fields under `data` (both breaking: see `UPGRADING.md`); index methods and hnsw distance.

### Breaking Changes

* **schema:** `AutoIncrement<T>` is now `Identity<T, "by-default">`: a `GENERATED BY DEFAULT AS
  IDENTITY` column rather than `SERIAL`. A column an earlier push made as a serial satisfies it and
  is left exactly as it is on every push; an explicit `Identity<...>` on it converts it.
* **schema:** a `Block`'s fields are under `data`: `Block<"hero", { heading: string }>` is
  `{ type: "hero"; data: { heading: string }; meta? }`, which is what Studio's block editor stores and
  what both generated files already said. It was `{ type: "hero"; heading: string }`, a shape no
  editor writes, so code typed from it read every field as missing on a page saved in Studio.
  `data` reads like a model's row: `Localized<string>` is the locale map and `Optional<T>` may be
  absent or null. Read `entry.data.heading` where you read `entry.heading`. `supatype push` moves
  rows stored in the old shape for you: each flat entry's fields go under `data`, a `Localized`
  field becomes a locale map in the project's default locale and a `RichText` field becomes
  Lexical editor state, in the model's `<table>_versions` snapshots too. `supatype diff` shows how
  many entries are pending and the push reports how many it moved. Push before those records are
  saved in Studio, which shows a flat entry's fields empty and leaves its text where nothing reads
  it. `UPGRADING.md` describes the move and keeps the SQL for doing it by hand.

### Features

* **schema:** identity and stored generated columns, as options on the field types:
  `Int<{ identity: "always" }>`, `BigInt<{ identity: "by-default" }>`, `SmallInt<{ identity }>`, and
  `generated: "<sql>"` on every scalar type (`Float<{ generated: "price * qty" }>`,
  `TSVector<{ generated: "to_tsvector('english', title)" }>`). `Identity<number>`,
  `Identity<bigint, "by-default">` and `Generated<string, "lower(name)">` resolve to exactly the
  options form, for the types (`string`) that take no options. `Generated<T, "<sql>">` is the
  supported form for a generated column on every type. `IdentityMode`,
  `ScalarFieldOptions` and `IntegerFieldOptions` name the options.

## 0.3.6 (2026-10-02)

### Breaking Changes

* **storage:** a bucket rule that is left out is refused, for every caller but the service role,
  the same as on a model. It used to mean "any signed-in user", so a bucket declaring only `read`
  and `create` let anyone signed in delete anyone's files. A bucket with no `access` at all now
  accepts no uploads. Declare each operation the bucket should allow; `supatype push` warns about
  each one left out.

### Features

* **storage:** `update` is a bucket rule, alongside `read`, `create` and `delete`, and governs
  overwriting an existing file (`x-upsert`). `BucketRule` names the union every operation takes.

* **access:** `After<TBase, TInterval>` and `Before<TBase, TInterval>` compose a base of `Now` or
  `StartOf<unit>` with a multi-unit interval, so "thirty days from now at 09:00" is expressible:
  `After<StartOf<"day">, { days: 30, hours: 9 }>`. `Ago` and `FromNow` carry a single amount and
  unit and could not say it. Both are unchanged and keep working; `After<Now, ...>` and
  `Before<Now, ...>` subsume them.

  The interval type is exact rather than merely assignable. A plain `extends TimeInterval`
  accepts `{ days: 30, dayz: 5 }`, because every unit is optional and excess property checking
  does not reach a type argument; the engine then reads the typo as absent and refuses the push,
  so the author hears about it minutes later instead of in the editor.

  The direction stays in the operand's name rather than becoming a signed number, because a
  negative amount reads as a double negative and the extractor already rejects one.
